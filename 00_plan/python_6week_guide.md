# 4. 문제를 푸는 방법

문제를 보자마자 정답을 확인하지 않는다.

```text
1. 문제 읽기
2. 5~10분 혼자 생각하기
3. 풀이 과정을 한국말로 적기
4. 코드 작성
5. 오류 확인
6. 막히면 힌트 확인
7. 그래도 안 되면 정답 확인
8. 다음 날 또는 주말에 다시 풀기
```

예:

```python
numbers = [3, 8, 11, 14, 20]

# 짝수만 새로운 리스트에 저장하기
```

코드를 바로 적기 어렵다면 먼저 생각한다.

```text
1. 빈 리스트를 만든다.
2. numbers에서 값을 하나씩 꺼낸다.
3. 현재 값이 짝수인지 확인한다.
4. 짝수라면 리스트에 추가한다.
```

그 다음 코드로 작성한다.

# 5. 문제 상태 표시

각 문제를 풀고 표시한다.

| 표시 | 의미 |
|---|---|
| ⭕ | 힌트 없이 혼자 해결 |
| △ | 힌트를 보고 해결 |
| ❌ | 정답을 확인해야 해결 |

토요일에는 **△와 ❌ 문제를 우선적으로 다시 푼다.**

# 6. 가장 중요한 공부 원칙

## ① 코드를 읽는 공부보다 직접 작성하는 공부

코드를 보고 이해하는 것과
빈 화면에서 작성하는 것은 다르다.

최종 목표:

```text
문제 읽기
↓
필요한 문법 떠올리기
↓
직접 코드 작성
↓
오류 수정
```

---

## ② 수업 코드를 문제로 바꾸기

수업에서 다음 코드를 배웠다고 하자.

```python
df.groupby("age_group")["survived"].mean()
```

집에서 코드를 그대로 읽지 말고 가린다.

그리고 문제로 바꾼다.

```text
연령대별 평균 생존율을 구하세요.
```

그 뒤 코드를 다시 작성한다.

---

## ③ 정답을 봤다고 끝내지 않기

정답을 보고 이해한 문제는 아직 완전히 익힌 것이 아니다.

1~3일 뒤 다시 풀었을 때 혼자 작성할 수 있어야 한다.

---

## ④ Python 기초는 6주 동안 계속 유지

Pandas나 머신러닝으로 넘어간 뒤에도 다음 문제는 계속 푼다.

```text
if
for
list
dict
function
lambda
```

Python 기초가 편해져야 Pandas와 머신러닝 코드도 편해진다.

# 9. 6주 후 목표 체크리스트

## Python

- [ ] if 문을 직접 작성할 수 있다.
- [ ] for 문을 직접 작성할 수 있다.
- [ ] list에 append 할 수 있다.
- [ ] dictionary를 반복할 수 있다.
- [ ] 문자열 메서드를 사용할 수 있다.
- [ ] 간단한 함수를 직접 만들 수 있다.
- [ ] return의 역할을 설명할 수 있다.
- [ ] try / except 구조를 이해한다.
- [ ] lambda / map 기본 사용법을 안다.

## NumPy

- [ ] array를 생성할 수 있다.
- [ ] ndim과 shape의 차이를 안다.
- [ ] indexing / slicing을 할 수 있다.
- [ ] reshape을 사용할 수 있다.
- [ ] axis의 기본 의미를 이해한다.

## Pandas

- [ ] DataFrame을 만들고 확인할 수 있다.
- [ ] 컬럼을 선택할 수 있다.
- [ ] 조건 필터링을 할 수 있다.
- [ ] sort_values를 사용할 수 있다.
- [ ] groupby를 사용할 수 있다.
- [ ] map / apply의 기본 사용법을 안다.
- [ ] 결측치를 확인하고 처리할 수 있다.
- [ ] merge의 기본 흐름을 이해한다.

## 데이터 전처리

- [ ] Feature / Target을 분리할 수 있다.
- [ ] Train / Test를 나누는 이유를 안다.
- [ ] Encoding이 필요한 이유를 안다.
- [ ] Scaling이 필요한 이유를 안다.
- [ ] fit과 transform의 차이를 이해한다.

## 머신러닝

- [ ] Classification / Regression의 차이를 안다.
- [ ] 모델 생성 → fit → predict 흐름을 안다.
- [ ] 기본 평가 지표의 의미를 이해한다.
- [ ] Model Parameter와 Hyperparameter 차이를 설명할 수 있다.
- [ ] Cross Validation의 기본 목적을 이해한다.
